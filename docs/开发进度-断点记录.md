### 2.8 管理后台（2026-09-18 新增）

**登录分流**：医护端登录页加了"医护登录 / 管理员登录"两个模式。
管理员登录成功后进入管理后台；普通医护选管理员登录会被明确拒绝（"该账号没有管理权限"）。

**后端接口**（`/api/admin`，仅管理员可用）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/overview` | 概览数字 |
| GET | `/api/admin/staff` | 账号列表 / 查找（工号、姓名、手机号、角色、状态） |
| GET | `/api/admin/roles` | 角色字典 |
| GET | `/api/admin/logins` | 登录记录 |
| POST | `/api/admin/staff` | 新建医护账号 |
| POST | `/api/admin/staff/{id}/reset-password` | 重置密码 |
| POST | `/api/admin/staff/{id}/status` | 启用 / 停用 |

**前端**：`frontend/admin/`（桌面布局，端口 5175），三个页面：概览、账号管理、登录记录。

**两级权限**：系统管理员（SUPER_ADMIN）管全院；科室管理者（DEPT_MANAGER / is_manager）
只能管本科室人员。普通医护调用管理接口一律 403。

**关于"查找账号密码"**——这里做了一个**刻意的取舍**：

用户想要"查找账号密码"，但系统只存 BCrypt 单向哈希，**任何人都还原不出原密码**（包括管理员）。
如果把密码改成可逆加密或明文，等于给全院账号留一把总钥匙，一旦库被脱走后果不可控。
所以做成了：

1. **查找账号**：按工号 / 姓名 / 手机号 / 角色 / 状态查，能看到"谁、什么角色、账号是否停用、最近什么时候登录过"；
2. **发密码**：新建账号或重置密码时，系统生成一次性密码，**界面上只显示这一次**，管理员当场交给本人；
3. **强制改密**：本人首次登录后会被要求改成自己的密码（`must_change_password`）；
4. **登录记录**：`/api/admin/logins` 可以查"这个账号最近是谁在用、有没有人试过密码"。

这样既满足日常管理需要，又不把全院密码变成可读数据。

## 四、过程中真实发现并修掉的问题（这节比功能清单重要）

| # | 现象 | 根因 | 处理 |
|---|---|---|---|
| 1 | 重置演示数据报 `permission denied for table patient` | 应用账号 `app_rw` 没有 TRUNCATE 权限 | **不给它放开权限**，改成按外键顺序 DELETE（权限最小化优先） |
| 2 | V1 里患者端能读到全部患者 | `p_patient_access` 的患者端分支只判断"是不是患者端"，没判断"是不是本人" | V2 迁移收紧为 `id = 当前患者`，并给任务/记录表补上患者端分支 |
| 3 | 患者令牌可以调用医护接口 | `SecurityConfig` 只写了 `authenticated()`，而患者也是"已认证" | `/api/**` 明确要求 `ROLE_STAFF`，患者端单独要求 `ROLE_PATIENT` |
| 4 | 种子数据两次被数据库拒绝 | 病理发布闸门要求"必须先审核 + 必须先写医生解读 + 高风险必须先告知" | 改成"录入 → 写解读 → 发布"三步。**这说明第 3 轮的病理闭环确实落在数据库层，应用层绕不过去** |
| 5 | 患者端测试出现假失败（接口明明返回了数据） | 我在 `.ps1` 里写了中文注释，PowerShell 5.1 按 GBK 解码无 BOM 文件，把注释下一行整行吞掉了 | 脚本全部清成 ASCII，并加了检查。项目"脚本只用 ASCII"这条规则不是洁癖 |
| 6 | 一键重置演示数据 500 | 前一天新增了"患者账号"表引用，重置清单没跟着更新外键顺序 | 在删患者前先删患者账号（医护账号保留，避免要重新种密码） |
| 7 | **后端的"抢占锁"接口从来没被前端调用过** | `api.js` 里定义了 `claimTask`，但没有任何页面用它——防重复打电话的机制在界面上是断的 | 打开任务详情即抢占锁；被同事占用时显示提示条（锁 30 分钟自动失效，不把人堵死）。已用两个账号在浏览器里验证 |
| 8 | 浏览器控制台 404 | 页面没有 favicon | 患者端内联一个 SVG favicon |
| 9 | 加完管理后台代码后，编译报满屏"找不到符号: 方法 getId()" | **本机默认 JDK 是 24，而 JDK 23 起 javac 不再使用类路径上的注解处理器**，Lombok 完全没生效。项目脚本因为 `dev-env.ps1` 里锁了 JDK 21 才一直正常 | 在 pom 里显式声明 `annotationProcessorPaths`；现在用 JDK 24 也能正常构建 |
| 10 | 管理后台打开是白屏 | 路由 catch-all 写成 `:pathMatch(.*)*`，少了开头的 `/`，路由表创建失败 | 改成 `/:pathMatch(.*)*` |
| 11 | 管理后台侧边栏一直显示"管理员"，不显示本人姓名 | `computed(() => getProfile())` 在登录前就算过一次，没有任何响应式依赖，之后不会重算 | 把当前登录人改成 `ref`，登录时更新 |
| 12 | 管理接口查询报 500"could not determine data type of parameter" | PostgreSQL 对 `(:param is null or ...)` 里的 null 参数无法推断类型 | 改成 `coalesce(cast(:param as bigint), 列)` 与显式 `cast(:param as text)` |

## 七、容易踩的坑（重启机器前先看这里）

1. **数据库端口是 55432，不是 5432。**
2. 后端由 `mvn spring-boot:run` 启动，直接关窗口会留下 java 进程占着 8080，
   下次启动报 `Port 8080 was already in use`。用 `tools/backend-stop.ps1`。
3. 演示数据会被联调测试消耗（每次 claim/complete 用掉一个任务）。
   测试跑完用 `tools/demo-reset.ps1` 复位。
4. 患者端验证码存在单机内存里，**只适用于单实例部署**；多实例必须换 Redis
   （`application-dev.yml` 里已预留 Redis 配置）。
5. 生产环境患者登录必须接短信通道：`app.portal.sms-mode` 非 dev 时接口会明确报
   "短信通道尚未配置"，不会假装发送成功。
6. 同一个手机号关联多位患者时，目前取第一位并在日志里留痕；正式上线前需要
   增加"病案号后四位"二次确认。
7. 所有 `.ps1` 脚本**必须只用 ASCII**（PowerShell 5.1 + GBK 解码问题，见第四节第 5 条）。
8. **不要用系统默认的 `java`/`mvn` 直接构建**：本机默认 JDK 是 24，虽然 pom 已修好，
   但项目脚本（`tools\backend-*.ps1`）会锁定 JDK 21，行为更可预期。
9. 测试会创建临时账号（`T8xxxx` 界面走查 / `T9xxxx` 接口测试），
   跑一次 `tools\demo-reset.ps1` 会自动清掉。
