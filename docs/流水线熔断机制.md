# 流水线熔断机制（防智能体互相循环）

> 建立：2026-09-22，给用户看的一页说明。
> 规则正文在仓库根目录 [AGENTS.md](../AGENTS.md)，机械闸门在 `tools\loop-guard.ps1`。

---

## 一、这条流水线本来是怎么转的

```
主智能体做完功能
   |
   v  贴「功能唤醒提示词」
测试智能体（QA）：跑测试 -> 出回执
   |
   v  PASS 之后贴「功能唤醒提示词」
功能需求完善智能体：找缺口 -> 打分 -> 裁决
   |
   v  ENHANCE_THEN_PROCEED（最多 3 条改进）
   |  「改进做完要回 QA 复测」
主智能体改代码 --------------------------> 回到 QA
```

问题就在最后那个箭头：**它没有次数上限**。于是三个会话可以无限互相唤醒，
每一轮都烧一遍 token、重启一遍服务、跑一遍全量回归，而代码可能一个字都没变。

## 二、为什么会停不下来（审计出的四个结构性原因）

| # | 原因 | 后果 |
|---|---|---|
| 1 | **这个目录没有 git**（实测 `fatal: not a git repository`），但 QA 提示词第 0 步写着"先记基线 `git status / git log -1`" | QA 拿不到"这轮改了什么"，只能**全量重测**；主智能体也**证明不了**"我改好了"，完善智能体只好把同样的建议再提一遍 |
| 2 | 两份提示词里**没有任何轮次上限**，只有"FAIL -> 修 -> 重测" | 环路天然无限 |
| 3 | 三个智能体是**三个独立会话，没有共享计数**，彼此只能靠写文档交接 | 谁也不知道"这是第几轮""这个问题提过没有" |
| 4 | **多个智能体同时写同一个文件夹**（审计当天实测：`PortalAuthService.java` 在无关时间点被改写，同时存在另一个存活的 `codex` 会话） | 测试测的、你改的、评审看的可能不是同一份代码，永远收敛不了 |

第 1 和第 4 条最要命：**没有版本控制 + 没有单一写入者 = 流水线在漂移中空转**。

## 三、现在的三道闸门

### 闸门 1：机械计数器 `tools\loop-guard.ps1`

每轮开工前必须过闸门，退出码 `0` 才放行，`2` 就是停：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\loop-guard.ps1 `
  -Action begin -Feature "一键拨号真正可用" -Stage qa
```

它自动拦下七种情况：

| 代号 | 拦什么 | 说明 |
|---|---|---|
| R1 | 熔断已被拉下 | `-Action stop` 之后，任何功能都开不了新一轮 |
| R2 | 全局预算用满 | 累计派发 40 轮为上限 |
| R3 | 上一轮没写回执 | 同一功能同一阶段连着开两次 |
| R4 | 单功能轮次超限 | QA / 修复各 3 轮，评审 1 轮 |
| R5 | **同一问题复发 2 次** | 用 `-Signature` 判重；复发即停，逼着换思路或找人 |
| R6 | **代码没变却要复测** | 上一轮 QA 判 FAIL、树里一个文件没动，直接拒测 |
| R7 | **有别的轮次还没闭合** | 单轨流水线；同时两个写手必出乱子 |

跑完必须登记回执，`-Signature` 是 R5 的判据，**不写就等于关掉了这条熔断**：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\loop-guard.ps1 `
  -Action end -Feature "一键拨号真正可用" -Stage qa `
  -Result FAIL -Signature "P1-桌面端无降级提示" -Note "16 项中 14 项通过"
```

2026-09-22 已做过的对抗验证（全部符合预期）：

```
T1 首轮              -> ALLOW  round=1/3
T2 同阶段连开两次     -> STOP   the previous 'fix' round was never closed
T5 同一签名再次 FAIL  -> STOP   breaker ENGAGED / exit 2
T6 熔断后再开轮       -> STOP   circuit breaker is ENGAGED
T7 ack 不带说明       -> 拒绝   exit 1
T8 ack 带用户决定     -> 解锁，并增加预算
```

### 闸门 2：仓库级规则 `AGENTS.md`

放在项目根目录，**在这个目录里工作的每个 Codex 智能体都会自动加载**。
里面写死了预算表、四个自动熔断条件、单一写入者，以及"必须停下来问用户的四种情况"。
它是唯一能覆盖所有会话的东西：新开的窗口不用你重新叮嘱。

### 闸门 3：提示词里加上限

《测试智能体-提示词集》《功能需求完善智能体-提示词集》开头都加了「熔断优先」一节，
流程第 0 步改成先过闸门、先取指纹，流程图里那条无上限的箭头也标上了上限。

## 四、急停与恢复

```powershell
# 拉闸（对所有功能生效）
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\loop-guard.ps1 `
  -Action stop -Feature "*" -Note "用户要求暂停"

# 看现在卡在哪一环
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\loop-guard.ps1 -Action status

# 你拍板之后才能解锁（必须写清是谁、什么时候、为什么）
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\loop-guard.ps1 `
  -Action ack -Feature "一键拨号真正可用" -Note "用户 2026-09-22 同意继续"
```

台账在 `tools\.pipeline\ledger.tsv`，只增不删，方便你事后查"这个功能到底耗了几轮"。
它是唯一允许三个智能体都写的路径。

## 五、熔断触发时，智能体必须给你什么

不要"再试一次看看"。接到 STOP 时，交给你的必须是这四样：

1. 现在是第几轮、哪个阶段；
2. 卡在哪一条规则（reason 原文）；
3. 已经试过什么（附回执与证据）；
4. 需要你提供什么（密码 / HIS 导出格式 / 拍板 / 授权）。

## 六、还没做、需要你定的两件事

1. **要不要 `git init`。** 一条命令、可回滚。做了之后"本轮改了什么"就有权威答案，
   R6 那条熔断会准得多，出问题也能回退。仓库根目录已有 `.gitignore`，显然是当初打算用的。
2. **要不要清理 `dist-deploy\`。** 现在 274 MB，其中 `followup-demo.zip` 68 MB、
   `followup-fix2.zip` 61 MB，是历史补丁包。删之前要你点头。

另外，`tools\.pipeline\` 是流水线台账，将来若启用 git，建议**不要**把它加进 `.gitignore`，
否则"第几轮"的历史又丢了。
