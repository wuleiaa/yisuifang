# 部署原理（大白话）与后续完善清单

> 面向非技术读者：解释"为什么上云要这么多步"，以及系统接下来要补什么。

---

## 一、为什么需要这些步骤

### 用开一家实体店打比方

| 部署步骤 | 相当于 | 为什么必须做 |
|---|---|---|
| 买云服务器 | **租店面** | 你自己的电脑一关机就没了，得有个 24 小时开门的地方 |
| 装 Ubuntu | **装修** | 空店面没法营业，先得铺水电装门窗 |
| 装 Docker | **装标准货架** | 数据库、网站、缓存各自装箱，一个坏了不连累别人 |
| 传部署包 | **把货搬进店** | 服务器上没有你的程序 |
| 生成密钥填 .env | **配保险柜密码** | 密码和程序分开存放，程序被拿到也打不开数据 |
| 启动容器 | **开门营业** | 前面都是准备，这一步才真正跑起来 |
| 开防火墙端口 | **开大门** | 云服务商默认全锁着，得明确告诉它开 80/443 |
| 买域名+解析 | **挂门牌号** | 不然顾客只能记"116.4, 39.9"这种数字地址 |
| 配 HTTPS | **装防盗门+验身份** | 没有它浏览器会警告"不安全"，密码还是明文传输 |

### 一句话总结

上云的每一步，都是在把"**我电脑上能跑的东西**"翻译成"**别人能安全访问的服务**"。

翻译过程会多出四样本地不需要的东西：

- **网络**：本地 `127.0.0.1` 只有自己能访问，云上全世界能访问
- **安全**：本地不用防人；云上必须防，所以有防火墙、密钥、证书
- **稳定**：本地崩了重启就行；云上崩了要给用户交代，所以有健康检查、自动重启
- **隔离**：本地软件挤一起；云上容器分开，互不干扰

### 为什么"本地跑通"不等于"云端能跑"

这次踩的 5 个坑，**没有一个是代码写错**，全是环境差异：

| 坑 | 本地为什么不会出现 |
|---|---|
| `pg_admin` 命名非法 | 本地用内置账号 `postgres`，没建过这名字 |
| 初始化脚本被跳过 | 本地是 Flyway 跑迁移，容器里是另一套机制 |
| `alias` 路径算错 | 本地用 Vite 开发服务器，没有 nginx |
| 正则劫走子应用资源 | 同上 |
| Vite 没设 `base` | 开发服务器自动处理路径，打包后才暴露 |

**这就是开发环境与生产环境的本质区别**：同一套代码，在两个地方面对完全不同的规则。

## 三、域名与"能被搜到"

### 两件不同的事，别混淆

| 说法 | 含义 | 要不要做 |
|---|---|---|
| **通过网址访问** | 输入 `https://xxx.com` 能打开系统 | ✅ 要，这正是买域名的目的 |
| **被搜索引擎收录** | 百度搜"随访系统"能搜到你的站 | ❌ 不要，已主动屏蔽 |

### 为什么不能让它被搜到

这不是技术限制，是合规要求：

1. 系统里有患者姓名、诊断、联系方式，属于敏感数据
2. 项目铁律第 2 条写明敏感数据不得外传
3. nginx 里已加 `X-Robots-Tag: noindex, nofollow`，主动告诉搜索引擎不要收录

如果哪天你在百度搜到了自己的系统，说明配置出了问题——那意味着**别人也能搜到患者的页面**。

### 买域名要做的事

1. 在腾讯云/阿里云搜个名字买下来（`.top`/`.xyz` 首年 10–30 元）
2. **实名认证**（个人身份证，1–2 小时通过）
3. 加一条 **A 记录**指向 `43.129.75.228`
4. 告诉我域名，我带你签 HTTPS 证书（免费，10 分钟）
5. 香港服务器**不需要备案**

## 附：排查思路（这次学到的）

页面打不开时，按这个顺序看：

1. **服务器上能开吗** → `curl -s localhost/health`
2. **nginx 有报错吗** → `docker compose logs nginx | tail -20`
3. **请求的路径对不对** → 看日志里浏览器请求了什么路径（这次就是靠这个发现的）
4. **文件在不在** → `docker compose exec nginx ls /var/www/followup/...`

**心法**：不要猜，去读日志。这次 5 个坑里有 3 个是"沉默失败"——不报错、只是不干活，
只能靠对比"预期 vs 实际"来发现。
