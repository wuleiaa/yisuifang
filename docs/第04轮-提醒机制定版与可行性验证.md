## 一、没有企业微信，第一版怎么提醒（本轮重点）

先说一个我上一轮**漏掉的重要方案**，它其实比企业微信门槛更低。

### 1.1 ★ 微信订阅消息：iOS 和安卓通吃的免费方案

微信有两套消息推送能力，之前我只讲了公众号那一套，漏了**小程序订阅消息**这一套：

| | 小程序订阅消息 | 公众号订阅通知 |
|---|---|---|
| 谁收到 | 用过你小程序的人 | 关注了公众号的人 |
| 收费 | **免费** | **免费** |
| 在 iOS 上 | ✅ 收到微信通知横幅 | ✅ 收到微信通知横幅 |
| 门槛 | 小程序上线即可 | 公众号须为**服务号** |
| 订阅方式 | 用户点一次"允许" | 用户点一次"订阅" |

**关键点：微信的"服务通知"会像普通微信消息一样，在手机锁屏时弹出横幅、响铃、震动。**
医生在 iOS 上收到的效果，和收到一条微信消息完全一样。

而且——**医疗类目的小程序可以申请"长期订阅消息"**，用户授权一次之后可以长期接收，
不需要每次授权。这正是我们需要的。

### 1.2 那么第一版的提醒矩阵就是（全部零成本）

| 层级 | 渠道 | 覆盖端 | 费用 | 能力 |
|---|---|---|---|---|
| **第 1 层** | **App/网页内的待办列表** | 全部 | 0 | **权威数据源，永不丢失** |
| **第 2 层** | **安卓 App 本地定时通知** | 安卓 | 0 | **闹钟式弹窗（响铃+震动+横幅）** |
| **第 3 层** | **微信订阅消息** | **iOS + 安卓** | 0 | **锁屏通知横幅（效果等同收到微信消息）** |
| **第 4 层** | **开屏强制提醒** | 全部 | 0 | 打开 App 时若有待办，直接全屏弹出 |
| 扩展位 | 企业微信推送 | iOS + 安卓 | 0 | **第二阶段接入，3 天工作量** |
| 扩展位 | 短信 | 全部 | 约 8 元/年 | 仅在逾期时发送，可开关 |

**这一套组合下来，成本是 0 元，iOS 和安卓都能收到提醒。**

### 1.3 第 2 层的关键技术点：为什么安卓本地通知不用花钱也不用服务器

因为**随访时间在任务生成时就已知了**。比如"术后 3 天电话回访"，
在患者出院当天系统就算出了准确的提醒时刻，App 可以直接把它写进手机的**系统级定时器**。

```
护士录入出院信息 
   → 服务端按路径模板生成随访任务（术后1天/3天/1个月…） 
   → 计算每个任务的提醒时刻 
   → 医生手机上的 App 拉取任务，把提醒时刻登记到手机系统定时器 
   → 到点，系统直接弹窗响铃（不经过服务器、不依赖网络）
```

**好处：**

- **零成本**：不用买推送服务（极光/个推的付费版）；
- **离线可用**：医生手机没网也能弹；
- **不被"杀后台"影响**：系统级定时器优先级高于普通后台进程；
- **可靠兜底**：即使被系统清理，打开 App 时重建定时器（第 4 层补救）。

### 1.4 iOS 的处境（诚实说明）

| 场景 | iOS 能做到什么 |
|---|---|
| 医护用安卓手机 | ✅ 闹钟式弹窗，体验最好 |
| 医护用 iPhone | ✅ 收到微信订阅消息通知横幅（和收到微信一样），❌ 无法做到强制全屏弹窗 |
| 打开系统时的兜底 | ✅ 打开 H5/小程序，若有待办直接全屏展示 |

**给院方的话术建议**（避免被当成缺陷）：

> "iPhone 出于系统安全限制，不允许任何第三方应用在后台强制弹窗，
> 这是苹果的限制，微信、支付宝也一样。我们采用微信官方通知的方式送达，
> 医生收到的效果和收到一条微信消息一样，不会漏掉。"

### 1.5 为将来的企业微信预留（架构上做渠道抽象）

即使第一版不用企业微信，我也会在代码里做一个**消息渠道抽象层**：

```java
public interface NotificationChannel {
    void send(NotificationMessage msg);
    boolean supports(Staff staff);
}
// 实现类：InAppChannel / AndroidLocalChannel / WechatSubscribeChannel
//         / WecomChannel（预留空实现）/ SmsChannel（预留）
```

这样将来医院上了企业微信，**只需要新增一个实现类，不动任何业务代码**。
这是"易于维护"的具体含义。

## 二、提醒节奏定版（按你的要求）

你的原话："前一天提醒明天要做的，或当天提醒今天要做的。然后每隔 2 小时提醒一次。"

我完全按这个实现，但加了**两个保护**（不加会出问题）：

### 2.1 提醒时间线

| 时间 | 提醒内容 | 提醒对象 |
|---|---|---|
| **T-1 日 18:00** | 「明天有 3 条随访任务，请提前安排」 | 主管医生 + 搭档护士 |
| **T 日 08:00** | 「今天有 3 条随访任务待处理」 | 主管医生 + 搭档护士 |
| **T 日 10:00** | 未完成的逐条提醒 | 责任人 |
| **T 日 12:00** | 同上 | 责任人 |
| **T 日 14:00** | 同上 | 责任人 |
| **T 日 16:00** | 同上 | 责任人 |
| **T 日 18:00** | 同上（附"今日即将结束"） | 责任人 + 搭档护士 |
| **T+1 起（逾期）** | 每天 08:00 / 12:00 / 17:00 各一次 | 责任人 |
| **逾期 ≥ 3 天** | 进入"逾期看板"，护士长/主任可见 | 科室质控视图 |

### 2.2 保护一：夜间免打扰

**22:00 – 07:00 不发送任何提醒。**
医生半夜被弹窗吵醒，第二天就会把通知关掉，整个提醒机制就废了。
免打扰时段可配置。

### 2.3 保护二：逾期任务降频

"每 2 小时一次"在任务逾期第 10 天的时候会变成骚扰（一天 6 次 × 30 天 = 180 次）。
所以设计成：

| 状态 | 频率 |
|---|---|
| 当天（T 日） | 每 2 小时一次，共 5 次 |
| 逾期 1–3 天 | 每天 3 次 |
| 逾期 4–14 天 | 每天 1 次（早上） |
| 逾期 > 14 天 | 只在"逾期看板"显示，不再主动打扰 |

**但任务永远不会消失**——它一直躺在待办列表和逾期看板里，
直到有人处理完。**提醒可以降频，任务不能丢失。**

### 2.4 关于"升级到护士长/主任"

你第 3 轮的回答里没有提到要升级给护士长，所以我**降级处理**：

| 原来的设计 | 现在的设计 |
|---|---|
| 24 小时自动升级给护士长 | 改为**不自动打扰护士长**，只出现在她的"逾期看板"里 |
| 72 小时升级给科主任 | 同上，改为看板统计，不做打扰式提醒 |

**理由**：三甲医院科室主任每天很忙，如果系统频繁给他弹"某某医生没回访"，
第一天就会被要求关掉。**用"看板"代替"骚扰"更符合医院实际。**
当然这一条也做成可配置，如果你们科室希望升级提醒，改个开关就行。

## 三、存储重新测算（病理 PDF 不上传后）

你说病理报告**只录文字结论，不上传 PDF**，这让容量问题基本消失了：

| 项目 | 第 3 轮测算（含 PDF） | **本轮测算（不含 PDF）** |
|---|---|---|
| 数据库 | 8 GB | **8 GB** |
| 病理报告文件 | 10–20 GB | **0** |
| 检查图片 | 5–20 GB | 0（暂不做） |
| 备份 | 10 GB | **5 GB** |
| **合计** | 33–48 GB | **约 13 GB** |

### 3.1 结论

- **云服务器 60 GB 系统盘完全够用**，甚至用三年都不用扩容；
- 也不需要额外的对象存储，**省掉 72 元/年**；
- **你的 200–300 元预算，比上一轮估算的更宽裕了。**

### 3.2 但有一个提醒

如果以后科室想加"检查图片上传"（比如胃镜照片、CT 片子），容量会立刻紧张。
所以我在设计上会**预留文件存储接口**，但第一版不启用。
到时候如果医院用内网 NAS，可以直接挂载，零成本。

## 五、本轮交付：可点击的交互原型

光看文档不如上手点。我做了一份**可直接在浏览器打开的原型**，
模拟了医护端和患者端的完整流程，你可以拿给科室医生和院领导看。

**文件位置**：`prototype/index.html`（双击即可打开，无需安装任何软件）

**原型包含的流程：**

```
医护端（安卓 App 风格）
  登录 → 今日待办列表 → 闹钟式提醒弹窗 → 患者详情
       → 一键拨号 → 填写回访记录 → 提交
       → 病理报告录入 → 医生审核 → 发布给患者

患者端（微信小程序风格）
  首页 → 我的随访时间轴 → 病理报告（医生解读）
       → 复诊提醒 → 个人信息
```

> ⚠️ 这只是**界面原型**，用于确认需求是否理解正确，不是最终产品。
> 数据是假的，功能是演示性质的。真正的系统会在确认原型后开始开发。

   （即使不是服务号也没关系，小程序订阅消息这条路依然可用。）

2. **原型看完后，哪里的业务流程和你科室的实际做法不一致？**
   请具体指出，我第 5 轮一并修正。特别是：

   - 回访表单要填哪些字段？
   - 患者端首页你最希望患者第一眼看到什么？

3. **回访记录的表单内容**，能否给我一份你们科室现在实际在用的：
   (a) 有没有现成的纸质回访单或 Excel 表？有的话拍照给我，我照着做。
