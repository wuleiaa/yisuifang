# 安全加固记录（2026-09-22 晚）

> 背景：配 HTTPS 时顺手做上线前检查，发现"强制改密"只是界面上的装饰，
> 以及一批审计日志形同虚设。这一轮把这几处补齐，并已上线验证。

## 一、发现的问题（都有证据）

| # | 问题 | 当时的证据 |
|---|---|---|
| 1 | **"首次登录必须改密"能被绕过** | 用公开的默认口令 `Followup@2026` 登录系统管理员 A0001，拿到令牌后直接 `GET /api/admin/staff` → **200**，完整员工名单（含手机号脱敏值、登录时间）全部返回。所谓"必须先改密"只是前端跳转，接口层没有任何拦截 |
| 2 | **停用账号后旧令牌还能用** | 令牌有效期 8 小时，而账号状态只在登录那一刻检查。停用一个人之后，他手上那个令牌还能继续干活，最长 8 小时 |
| 3 | **改密失败的审计被事务回滚**（待办 #3） | `changePassword` 里"原密码不对"先写审计再抛异常，而审计写在同一个事务里 → 异常一回滚，最该留痕的"有人试改别人密码"一条都不剩。线上库 `audit_log` 里 `STAFF_CHANGE_PASSWORD` 只有 SUCCESS，没有任何 FAIL |
| 4 | **登录日志不记 IP 与 User-Agent** | 线上 `login_log` 共 47 行，**带 IP 的 0 行**。也就是说"登录记录"只能看到"谁在什么时候登录过"，看不到来源，事后无法判断是否被盗用 |
| 5 | **管理后台没有改密入口**（待办 #4） | A0001 被要求改密，但后台里找不到地方；只能绕到医护端去改 |
| 6 | **演示账号仍在使用公开的默认口令** | A0001 / N0455 / N0001 的密码还是仓库文档里写明的 `Followup@2026`，而线上是任何人可访问的 HTTPS 站点 |

## 二、改了什么

### 后端

| 文件 | 改动 |
|---|---|
| `security/JwtAuthFilter.java` | 除了识别身份，每次带令牌的请求再查一次账号：① 账号被停用/删除 → 立即 401；② `must_change_password=true` 时只放行 `/api/auth/me` 与 `/api/auth/change-password`，其余 `/api/**` 一律 **403 + 41005** |
| `service/AuditLogService.java`（新增） | 审计日志**唯一写入口**：独立事务（REQUIRES_NEW）+ 自动带 IP/UA。改密、建号、重置、停用、患者端登录全部改走它 |
| `common/ClientInfo.java`（新增） | 从当前请求取客户端 IP（优先 `X-Real-IP`，其次 `X-Forwarded-For` 最后一段，最后退回 socket 地址）与 User-Agent，并做长度截断 |
| `service/LoginLogService.java` | 登录日志写入 `ip` 与 `user_agent` |
| `service/AuthService.java` / `AdminService.java` / `PortalAuthService.java` | 各自那份重复的 `insert into audit_log` 全部删掉，统一走 `AuditLogService`（改密失败因此不再被回滚） |
| `common/ErrorCode.java` | 新增 `PASSWORD_CHANGE_REQUIRED(41005)` |
| `bootstrap/DevDataSeeder.java` | **仅 dev 演示账号**不再标记"必须改密"（否则本地冒烟测试每次都要先改密码）。真正的安全边界不变：管理后台建号 / 重置密码生成的是一次性口令，仍然强制本人首次登录后修改 |

### 前端

| 文件 | 改动 |
|---|---|
| `frontend/src/api.js`、`frontend/admin/src/api.js` | 收到 **41005** 时自动跳到改密页（原来只会弹一句"没有权限"） |
| `frontend/admin/src/views/ChangePassword.vue`（新增） | 管理后台的改密页（待办 #4） |
| `frontend/admin/src/router.js` | 新增 `/change-password` 路由；处于"待改密"状态时，路由守卫只允许停在改密页 |
| `frontend/admin/src/App.vue` | 侧边栏加「修改密码」入口 |
| `frontend/admin/src/views/Login.vue` | 登录后被要求改密就直接进改密页 |

### 测试工具

| 文件 | 改动 |
|---|---|
| `tools/security-smoke-test.ps1`（新增，14 项） | 专门守上面这几条：待改密账号被拦（403/41005）、改完同一个令牌立刻可用、停用后令牌立即失效（401/41003）、改密失败仍留审计、登录日志带 IP/UA |
| `tools/api-smoke-test.ps1`、`tools/admin-smoke-test.ps1` | ① 三个演示账号可分别指定密码（线上各自改过，不再假设同一个）；② 健康检查同时兼容 `/health` 与 `/actuator/health`；③ 需要直连本地库的断言，只有在**确实在测本地**时才跑，否则显示 SKIP（避免"对着线上却查本地库"的假绿） |

## 六、还没做的（留给下一轮）

1. **令牌不能主动吊销**：改密码/停用后靠"每请求查一次账号状态"兜住了，但用户主动"退出登录"仍然只是前端删掉令牌（服务端那串令牌在有效期内依然可用）。彻底做法是加一个令牌版本号（`account.token_version`）或黑名单。
2. **登录失败次数与锁定没有告警**：现在只会锁账号，没人收到通知。
3. **患者端验证码存在单机内存**：多实例部署必须换 Redis（代码注释里已标注）。
4. **`dev` 演示 profile 会自动建演示账号**（待办 #7）：正式给医院用之前必须换成"手工建管理员 + prod profile"。
