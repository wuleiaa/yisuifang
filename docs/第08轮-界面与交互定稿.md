## 一、住院号确认与"病案号"补充

你确认住院号全院统一，那么**每次住院一个号**，这个号是每次住院的唯一标识。

但这里有个必须补上的问题：

> **同一个患者三年内住院 3 次，会有 3 个不同的住院号。
> 系统怎么知道这 3 条记录是同一个人？**

如果识别不出来，患者会被建成 3 个独立的"人"，随访记录散落三处，
医生看不到完整病史——**这在临床上是不能接受的**。

### 1.1 解决方案：增加病案号字段

我在患者表（`patient`）上新增了 `medical_record_no`（病案号）：

```
patient（患者，终身唯一）
  ├── medical_record_no  病案号 ← 新增，跨多次住院不变
  └── name / phone...    姓名、手机号等

encounter（住院记录，一次住院一条）
  ├── inpatient_no       住院号 ← 每次住院一个
  └── admit_date / discharge_date ...

关系：1 个患者 → N 次住院
```

**如果你们医院的系统里本来就有"病案号"或"门诊号"这类终身不变的号，
就用它填这个字段。如果没有，可以留空，系统用下面的规则识别。**

### 1.2 导入时的患者匹配规则（三级）

护士导入 Excel 时，系统按这个顺序判断"这条记录属于哪位患者"：

| 优先级 | 匹配条件 | 处理 |
|---|---|---|
| 1 | **病案号相同**（若填了） | 直接认定同一患者 |
| 2 | **手机号相同 且 姓名相同** | 认定为同一患者（并提示"该患者已有 N 次住院记录"） |
| 3 | 姓名 + 性别 + 年龄 相同，但手机号不同 | **不自动合并**，进入"疑似重复"列表，由护士人工确认 |
| — | 都不匹配 | 新建患者 |

**第 3 条特别重要**：绝不自动合并。因为同名同姓同年龄的老人在一个科室里
完全可能出现，自动合并会把两个患者的病史混在一起——**这是严重的医疗差错**。
宁可让护士多确认一次。

### 1.3 界面上怎么体现

患者详情页会显示：

```
张*春  男 58岁
病案号 0003721  ·  手机 138****5678

住院历史（3 次）
├─ 2026-09-06 ~ 09-12   住院号 2026003721   内镜下结肠息肉切除术
├─ 2025-03-11 ~ 03-15   住院号 2025001882   上消化道出血
└─ 2024-08-02 ~ 08-07   住院号 2024009911   十二指肠球部溃疡
```

## 三、六个关键交互设计

### 3.1 待办列表：按"紧急度 + 时间"排序，不按患者

第 5 轮我问过你排序方式，这里给出我的设计：

```
┌────────────────────────────────────┐
│  2026年9月15日 星期二                 │
│  3 条待办    逾期 1 · 今日 2 · 本周 7  │
└────────────────────────────────────┘

【已逾期】──────────────────────────
  张*春  胆总管结石（ERCP）   逾期 2 天        [立即回访]
  李*明  胆囊结石             逾期 1 天        [立即回访]

【今天】────────────────────────────
  刘*明  上消化道出血         今天 18:00       [开始]

【本周】────────────────────────────
  赵*国  消化性溃疡           09-18           [查看]

【已完成】──────────────────────────
  孙*丽  术后 3 天回访  王护士代录  ✓
```

**为什么这样排**：

- **逾期在最上面**，因为逾期任务才是真正有风险、需要马上处理的；
- **不按患者分组**，因为护士关心的是"今天要做什么"，不是"有哪些患者"；
- **已完成折叠**，减少视觉噪音；
- 每条显示 **路径标签**，护士一眼看到"这是哪条随访路径的任务"。

### 3.2 多路径合并显示

当一个患者同时有两条路径、且任务落在同一天：

```
┌────────────────────────────────────┐
│ 王*华  男 62岁           ⚠ 2 条任务  │
│                                    │
│ ▸ 胆总管结石（ERCP 取石术后）        │
│    术后 3 天电话回访   今天 09:00    │
│                                    │
│ ▸ 胆囊结石（腹腔镜胆囊切除术后）      │
│    术后 3 天电话回访   今天 09:00    │
│                                    │
│              [ 一次完成两条 ]  ← ★  │
└────────────────────────────────────┘
```

**"一次完成两条"是我加的设计**：
两条任务时间点相同、（通常是）同一个电话，
让护士填一份表单、一次性标记两条完成，**避免打两通电话或填两遍**。

系统会在两条任务上**各记一条回访记录**，`followup_task_log` 里分别留痕，
**数据上是两条独立任务，操作上是一次完成**。

### 3.3 回访表单：目标是"30 秒填完"

护士一天要打十几通电话，表单每多一个输入框，实际成本都成倍放大。
所以设计原则是：**能点就不要打字**。

```
┌── 回访记录 ────────────────────────┐
│                                    │
│ 是否接通                            │
│ [已接通] [未接听] [号码错误] [拒访]   │  ← 点选，默认"已接通"
│                                    │
│ 联系的是  [本人] [家属]              │
│                                    │
│ 有无以下症状（可多选）                │
│ [腹痛] [便血] [呕血] [黑便]           │
│ [发热] [黄疸] [恶心呕吐] [无明显症状]  │  ← 点选
│                                    │
│ 恢复情况                            │
│ [恢复良好] [轻度不适] [明显异常]       │
│                                    │
│ 用药依从性                          │
│ [按时服药] [偶尔漏服] [已自行停药]     │
│                                    │
│ 结论与指导  ┌──────────────────┐    │
│            │ 模板：术后恢复良好...│    │  ← ★ 常用语一键填入
│            └──────────────────┘    │
│                                    │
│ 下一步                              │
│ [继续计划] [提前复诊] [上报医生] [结束]│
└────────────────────────────────────┘
```

**★ 结论栏的"常用语模板"**：预置 5–8 条高频结论，
点一下自动填入，护士只需微调。这一条能把单次填写时间从 2 分钟压到 30 秒。

### 3.4 异常快速上报：任何位置都能一键触发

按第 7 轮定的规则，**不等提交**：

```
护士点了 [呕血] 或 [黑便] 或 [明显异常]
        ▼
立即弹出（覆盖在当前页面之上）
┌───────────────────────────────────┐
│         ⚠️  发现异常症状             │
│                                   │
│  患者：张*春（男 58岁）             │
│  症状：呕血、黑便                   │
│                                   │
│  建议立即通知主管医生               │
│  李医生 · 消化内科                 │
│                                   │
│  [ 立即通知 ]      [ 仅记录不通知 ]  │
└───────────────────────────────────┘
        ▼
点"立即通知" → 立刻推送医生（含安卓本地通知 + 小程序订阅消息）
             → 生成紧急任务，15 分钟内必须响应
             → 记录操作日志
```

**关键：这个弹层是全局的**——护士在患者详情页、在列表页、
甚至在填写表单填到一半时，都能触发。不需要先保存。

### 3.5 一键拨号与号码保护

```
┌────────────────────────────────────┐
│  患者联系                            │
│                                    │
│  本人  张*春    138****5678  [📞]   │
│  儿子  张*明    139****1234  [📞]   │
│                                    │
│  [ 查看完整号码 ]  ← 需指纹/密码验证  │
└────────────────────────────────────┘
```

**设计要点**：

| 点 | 说明 |
|---|---|
| 直接显示 4 个候选号码的脱敏形式 | 一键拨号不需要看到完整号码 |
| 一键拨号 | 点 `[📞]` 直接呼出，**不需要解密**（由 App 调系统拨号） |
| 查看完整号码 | 必须二次验证，且**写入审计日志**（谁、何时、看了谁的号码） |
| 拨号后自动记录 | 返回 App 时提示"刚才拨打的是 138\*\*\*\*5678，用时 3 分 42 秒，填入表单？" |

### 3.6 质控看板（护士长视角）

│                                    │

护士长想看就看，系统不会主动弹窗催她。

## 四、视觉与易用性规范

### 4.1 配色

| 用途 | 颜色 | 说明 |
|---|---|---|
| 主色 | `#1E6FFF` | 医疗蓝，专业、可信 |
| 辅色 | `#0EA5A4` | 青绿，用于健康/完成类信息 |
| 危险/异常 | `#EF4444` | 仅用于逾期、异常症状、高风险 |
| 警告 | `#F59E0B` | 需关注、待审核 |
| 成功 | `#10B981` | 已完成 |
| 背景 | `#F4F6FB` | 浅灰蓝，减少长时间阅读疲劳 |

**原则：红色只在真正紧急的地方出现。** 如果到处都是红色，红色就失效了。

### 4.2 字号（针对科室实际使用者优化）

科室里用这套系统的医生护士，年龄多在 30–55 岁，
不少人会有老花或长时间看手机后的视觉疲劳。所以：

| 元素 | 字号 | 常规 App 对比 |
|---|---|---|
| 患者姓名 | **17px** | 通常 15px |
| 正文 | **14px** | 通常 13px |
| 标签/辅助文字 | **12px** | 通常 11px |
| 按钮文字 | **14px** | 通常 13px |
| 行高 | **1.7–1.9** | 通常 1.5 |

**宁可一屏少放两条，也要保证看得清。**

### 4.3 操作成本控制

| 原则 | 落地 |
|---|---|
| 关键操作不超过 3 步 | 回访：打开 App → 点任务 → 填表提交 |
| 常用操作不用打字 | 全部改成点选 + 常用语模板 |
| 危险操作必须确认 | 删除、批量改派、发布病理报告 |
| 操作可撤销 | 提交后 30 秒内可撤回（回访记录除外） |
| 断网可用 | 安卓 App 支持离线查看待办，联网后自动同步 |

## 八、本轮需要你回答的问题（3 个）

1. **你们医院的系统里，有没有"病案号"或"门诊号"这类终身不变的号？**
   有的话填到系统里，多次住院的识别就 100% 准确；
   没有也能用（靠手机号+姓名匹配），只是偶尔需要人工确认。

2. **待办列表的排序方式**（我设计的是"逾期置顶 + 按时间"），
   你科室的护士看了原型之后觉得顺手吗？有没有更符合她们习惯的方式？

3. **常用语模板**——能否请护士提供 5–8 句她们电话里最常说的话？
   比如"术后恢复良好，无腹痛便血，已告知注意饮食"。
   有了这些，回访表单的填写效率能提升好几倍。
