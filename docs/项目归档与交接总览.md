## 二、这个项目是什么

**消化内科随访管理系统**（XX 市第一人民医院呼吸/消化内科场景），三个端共用一个域名：

| 端 | 谁用 | 干什么 |
|---|---|---|
| 医护端 H5 | 医生 / 护士 / 护士长 | 登录、待办、回访表单、患者列表与详情、我的（改密） |
| 患者端 H5 | 患者 | 手机号+验证码登录、随访时间轴、问卷、病理报告 |
| 管理后台（桌面） | 系统管理员 / 科室管理者 | 概览、账号管理（建号/查号/重置密码/停用启用）、登录记录、**改密（2026-09-22 新增）** |

技术栈：Spring Boot 3.5（Java 21）+ PostgreSQL 16 + Redis 7 + Vue 3/Vite 三份前端 + Nginx + Docker Compose。
数据模型：**43 张表**（Flyway V1/V2/V3），后端接口 24 个（医护 9 / 患者 8 / 后台 7）。

规模参考：后端 60 个 Java 文件、前端 20 个 `.vue`、`tools` 34 个脚本、`docs` 24 份文档。

## 九、关键设计决策（含"为什么不那么做"）

| 决策 | 为什么 |
|---|---|
| 密码只存 BCrypt 哈希，管理员也查不到原密码 | 改成可逆加密等于给全院账号留一把总钥匙；管理员的职责是"发一次性密码"而不是"看密码" |
| 手机号 AES-256-GCM 加密 + 可检索哈希 | 密文防拖库、哈希支持按手机号查；密钥与数据库分离存放（`.env`），**丢了手机号不可恢复** |
| 审计/登录日志用独立事务（REQUIRES_NEW） | 最常见的审计对象恰恰是"失败的操作"，而失败会让主事务回滚 |
| "必须先改密"在**接口层**强制（403/41005），不只在前端 | 前端跳转不是安全边界；演示账号的初始口令是公开的 |
| 停用账号后每请求复查状态 | 令牌 8 小时有效，只在登录时校验会留下"停用后仍可操作"的窗口 |
| 前端 `index.html` 用 `expires -1` 而不是 `add_header Cache-Control` | nginx 里 location 出现任何 `add_header` 都会让 server 级安全头（`X-Robots-Tag` 等）**整片失效** |
| 旧的 `www/*/assets/*.js` 故意不删 | 用户浏览器可能缓存着旧 `index.html`，旧文件还在就不会白屏（最多慢一拍） |
| 没有启用 HSTS | 演示环境证书万一出问题，HSTS 会让用户连"点继续"的机会都没有；正式部署再评估 |
| 用 `docker-compose.override.yml` 叠加 HTTPS 而不是改主 compose | 主文件一个字不动，撤销 HTTPS 只要删一个文件 |

## 十、踩过的坑（改配置前先看这张表）

| # | 坑 | 症状 | 教训 |
|---|---|---|---|
| 1 | 超级用户名用 `pg_admin` | 容器 1.6 秒退出 | PostgreSQL 保留 `pg_` 前缀 |
| 2 | 初始化脚本挂成**目录** | 应用连不上库 | postgres 只执行 `.sh`/`.sql` 文件 |
| 3 | nginx `alias` + `try_files` | `/admin/` 404 | 用 `root` |
| 4 | 正则 `location ~* \.(js\|css)$` 劫走子应用资源 | 白屏 | 用 `^~` 前缀限定 |
| 5 | Vite 没设 `base` 就做子路径部署 | 白屏，服务器端完全正常 | 子路径必须 `base: '/admin/'` |
| 6 | ACME 校验目录用普通前缀 | certbot 永远 404 | 必须 `location ^~ /.well-known/acme-challenge/` |
| 7 | 在 location 里写 `add_header` | server 级安全头整片消失，患者页面会被搜索引擎收录 | location 里出现一条 `add_header`，server 级的全部不再继承 |
| 8 | 配置里写了 `ssl_certificate` 但证书文件不存在 | **整个 nginx 起不来**（不是那一个站点） | 签证书前先用 HTTP 引导版顶住 |
| 9 | 单文件挂载用 `mv` 覆盖 | 容器里读到的还是旧内容 | 用 `cp -f`（挂载跟 inode） |
| 10 | `docker compose` 里 `${SERVER_NAME}` 这类占位符 | 不会被替换（除非走 templates） | 演示环境直接写死域名 |

## 十三、已知风险（别当成"应该没问题"）

1. **2 核 2G 的机器**跑四个容器（app 限 512MB 堆），只适合演示；正式部署要按医院规模重新选型。
2. **香港服务器 = 数据出境**。现在里面只有假数据，所以没事；放入任何真实患者信息前必须换境内服务器并走备案与合规。
3. **演示环境跑的是 `dev` profile**（会自动建演示账号、验证码直接返回）。这是演示特性，也是风险。
4. **没有 git 历史**（正在补），改动只能靠补丁包和备份目录回溯。
5. **证书续期依赖 cron 与 80 端口**：如果哪天云防火墙把 80 关了，续期会在 90 天后的某个周一静默失败（日志在 `/var/log/followup-cert-renew.log`）。
