## 六、打补丁包的流程

```powershell
# 1. 本地构建
cd frontend; npm run build; npm run build:patient; npm run build:admin; cd ..
mvn -s backend\settings.xml -f backend\pom.xml -DskipTests clean package

# 2. 组装补丁（只放改动的部分）
#    后端全量替换 app.jar；前端替换 www/<端>/

# 3. 上传到服务器
scp "F:\医院回访小程序\dist-deploy\followup-fixN.zip" ubuntu@43.129.75.228:/home/ubuntu/

# 4. 服务器上
cd /opt/followup && unzip -o /home/ubuntu/followup-fixN.zip
docker compose restart app     # 只有后端改动才需要重启
```

**HTTPS 安装包（`followup-https1.zip`）不走上面这套**：它改的是 nginx 和 compose，
做法（含回滚）见《[HTTPS-配置与续期](HTTPS-配置与续期.md)》：

```bash
cd /opt/followup
unzip -o /home/ubuntu/followup-https1.zip
sudo bash https/install-https.sh    # 用 root 登录就去掉 sudo
```

装完之后服务器上多出这些文件（源码在仓库 `deploy/demo/`，改配置要在两个地方同步改）：

```
/opt/followup/docker-compose.override.yml   ← 443 端口 + 证书/校验目录挂载
/opt/followup/nginx/followup.conf           ← 当前生效（脚本会在引导版/HTTPS 版之间切换）
/opt/followup/nginx/followup-https.conf     ← HTTPS 正式版
/opt/followup/nginx/followup-http-only.conf ← HTTP 引导版
/opt/followup/nginx/letsencrypt/            ← 证书（certbot 写入）
/opt/followup/nginx/www/                    ← ACME 校验目录
/opt/followup/https/{install-https.sh,renew-cert.sh}
/etc/cron.d/followup-cert-renew             ← 每周一 03:17 自动续期
```

## 七、部署时踩过的坑（新窗口请务必先看）

| # | 坑 | 症状 | 教训 |
|---|---|---|---|
| 1 | 超级用户名 `pg_admin` 触犯 PostgreSQL 的 `pg_` 保留前缀 | 容器 1.6 秒就退出 | 别用 `pg_` 开头的角色名 |
| 2 | 初始化脚本挂成**目录**被跳过 | 应用连不上库（密码还是占位符） | postgres 只执行 `.sh`/`.sql` 文件 |
| 3 | `alias` + `try_files` 拼错路径 | `/admin/` 404 | 用 `root` 而不是 `alias` |
| 4 | 正则 `location ~* \.(js\|css)$` 劫走子应用资源 | 白屏 | 用 `^~ /assets/` 限定前缀 |
| 5 | Vite 没设 `base`，子路径部署 | **白屏，服务器端完全正常** | 子路径部署必须设 `base: '/admin/'` |
| 6 | ACME 校验目录用普通前缀 | certbot 校验永远 404（被末尾的 `location ~ /\.` 正则抢走） | 写 `location ^~ /.well-known/acme-challenge/` |
| 7 | 在 location 里写 `add_header` | server 级安全头（`X-Robots-Tag: noindex`）**整片消失**，患者页面会被搜索引擎收录 | location 里出现一条 `add_header`，server 级的就全部不再继承；缓存用 `expires` |
| 8 | 配置里写了 `ssl_certificate` 但证书文件不存在 | **整个 nginx 起不来**（不是那一个站点） | 签证书前先用 HTTP 引导版顶住，签完再切回来 |

**排查心法**：页面打不开时，先 `curl -s localhost/health`，再看 `docker compose logs nginx`，
**重点看日志里浏览器请求的路径对不对**（第 4、5 个坑都是靠这个发现的）。

## 八、两条必须守住的规矩

1. **`.ps1` 脚本只能用 ASCII** —— PowerShell 5.1 读无 BOM 文件按 GBK 解码，中文注释会导致语法错误（踩过两次）。
2. **不要用系统默认的 `java`/`mvn` 直接构建** —— 本机默认 JDK 24，虽然 pom 已修好，但项目脚本锁定 JDK 21，行为更可预期。
